## Mike's editor is usually open: be careful

- **Don't edit `project.godot`.** The open editor holds its own copy and
  will overwrite it. Register controls in code (`world.gd`
  `register_controls()`).
- **Don't run `--headless --import` on the real project.** It updates
  `.godot/imported` behind the editor's back, so the editor keeps showing
  stale textures until Mike uses Project → Reload Current Project.
- Mike saves scenes from the editor (adding `uid`s and `unique_id`s, and
  placing nodes himself), so **read a `.tscn` before editing it** and keep
  his changes. After a `.tscn` change, tell him to click **Reload** in the
  editor's prompt and not to save first.
- New PNGs that need mipmaps: write the `.import` file (copy
  `assets/props/radio_station.png.import`, drop the `uid`, `path` and
  `dest_files` lines, and set the `source_file`) **before** Godot first sees
  the PNG. The settings survive the import.

## Testing

- **Test on a scratch copy** of the project: copy `project.godot`,
  `icon.svg`, `scenes`, `scripts`, `shaders` and the needed `assets`
  folders, then run `--headless --import` on the copy.
- **Run tests with `--headless`.** A windowed test pops up on Mike's screen
  and can take his keyboard focus while he's playtesting. Use a window only
  for screenshots.
- Test scripts are SceneTree scripts: `godot --path <copy> -s test.gd -- args`.
  - `_ready` and group membership happen after the first frame, so
    `await process_frame` before looking things up.
  - Wait on **`physics_frame`**, not `process_frame` (the frame rate is
    uncapped). `physics_frame` fires *before* nodes run that tick, so wait
    two ticks before checking an input's effect. After a long pause,
    several physics ticks can run before the next `_process`, so also await
    `process_frame` when checking `_process` effects.
  - **Mouse:** Godot reads the real cursor for `get_global_mouse_position()`,
    so injected motion events don't move the aim. Swap in a player subclass
    with `_aim_point()` overridden (see the DEVLOG tests). `command.gd` and
    `radio_station.gd` use event positions, so injected events work there.
    Window coordinates = `root.get_final_transform() * (canvas_transform * world)`.
  - **Screenshots:** set `paused = true`, wait for
    `RenderingServer.frame_post_draw` with a frame limit, save
    `root.get_texture().get_image()`, then unpause. Background windows often
    stop drawing, so trust numeric checks over images.

## Art and world rules (see DEVLOG "World Scale & Lighting")

- Real-world scale: **1 m = 85.33 px** (`PX_PER_M`, in both `bs_common.py`
  and `world.gd`). Gameplay values are in metres.
- **Sun:** from the top-left, 40° from overhead (`bs_common.py`).
  - Static props render under that sun, with a separate shadow-catcher
    image normalised so that open-ground shadow = alpha 1, shown at 0.71.
  - Objects that **rotate in game** (rifle, helicopter, dish) render lit
    from **straight overhead**, and their shadows are drawn in Godot (an
    offset silhouette, or `shaders/shadow_sweep.gdshader` across the part's
    height range).
  - Squares turn by **picking pre-lit sheet frames**; never rotate a
    top-left-lit sprite.
- A character's shadows go in one `CanvasGroup` (fully dark inside, group
  alpha 0.71) so overlaps don't double-darken.
- Small detailed things render at 2–4× density and show at 1/N scale with
  mipmaps.
- With an overhead sun, **matte parts need a low specular level** (the
  `shine` parameter), or flat tops mirror the sun and look pale grey.
- **Thin, tall objects** (masts) need a narrow sun (~1°), because the shared
  8° sun blurs their shadows away.
- Things a square walks on (decks, cables) go in a ground layer below z 0;
  tall parts go above.

## Code conventions

- Every square is `scripts/soldier.gd`. Subclasses override
  `_move_intent()`, `_aim_point()` and `_wants_to_fire()` (`player.gd`,
  `squadmate.gd`).
- Shared constants (`PX_PER_M`, `ARENA`, sun, `COMMAND_COLOR`, controls)
  live in `scripts/world.gd`; load it with
  `const World = preload("res://scripts/world.gd")`.
- Groups: `player` (one) and `squad` (squadmates).
- Comments explain *why*. Match the existing doc-comment style (`##`).
- Menus use `scripts/ui_style.gd` (look) and `scripts/hold_popout.gd`
  (press-hold-slide-release pop-out); reuse them for any new menu.
- Don't name methods after Node built-ins (`request_ready`, `ready`,
  `process` and so on). A clashing signature is a parse error that silently
  breaks whichever scene uses the script.
- `main.tscn` places no squadmates or helicopters; tests must spawn their own.
